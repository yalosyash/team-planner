# QA: локальный запуск

Требуется Node.js 22.12 или новее. Из корня проекта:

```powershell
npm ci
npx playwright install chromium
npm run test:unit
npm run test:e2e
```

В Windows sandbox, если Node сообщает EPERM при realpath, перед командами:

```powershell
$env:NODE_OPTIONS='--preserve-symlinks --preserve-symlinks-main'
```

Каждый браузерный тест получает отдельный временный каталог установки
(data/settings/runtime), свободный порт и очистку в finally. Рабочая установка
и start.bat не запускаются. Ретраи отключены. Конфигурация: Chromium,
1440×900, ru-RU, Europe/Moscow. Playwright запускает собственный браузер.

`npm run test:e2e:report` открывает HTML-отчёт. При падении screenshot и trace
находятся в test-results/ и доступны из отчёта playwright-report/.
Эти каталоги и node_modules/ исключены из Git.

`npm run test:smoke` проверяет изоляцию серверов и перезапуск без браузера.
`npm run test:check` проверяет синтаксис JavaScript приложения, сервера и тестов.
`npm run test:unit` запускает Vitest и V8 coverage (HTML: coverage/index.html,
машинный итог: coverage/coverage-summary.json). Часовой пояс фиксирован:
Europe/Moscow; даты для todayISO задаются управляемыми часами. Порог покрытия
не установлен в сокращённом плане; процент относится только к dates.js,
calendar.js, plan.js и schedule.js, а не ко всему приложению. Vitest не запускает самостоятельные
Node-скрипты и Playwright-сценарии. Отсутствие тестов считается ошибкой.
`npm run test:node` запускает 11 Node-проверок (включая миграцию и HTTP).
`npm run test:windows` запускает installation.mjs; требует Windows и WSH.
Runner останавливается при первой ошибке; лимит каждого скрипта — 120 секунд.
Логи записываются в test-results/. Неизвестный набор и запуск Windows-набора
на другой ОС завершаются ошибкой.

Workflow `.github/workflows/tests.yml` запускается на push во все ветки,
pull_request и вручную. Отдельные задания: синтаксис/Node на Linux,
Chromium E2E на Linux и установка на Windows. В каждом — npm ci и Node 22.
Chromium устанавливается с системными зависимостями на чистом runner.
Vitest включён в Linux Node job; coverage прикладывается вместе с логами
при падении этого задания. QA result требует успеха всех трёх заданий,
включая отсутствие пропусков.
HTML-отчёт браузера сохраняется после завершения, логи Node/Windows — при
ошибке; срок хранения — 14 дней. Ошибки установки видны в логах Actions.
Общий лимит E2E — 5 минут, заданий — 15 минут; ретраи отключены.

Пробел: старые `split-storage-browser.mjs` и `release-transfer-ui.mjs`
не включены в обязательный набор: прежний локальный запуск остановился
на CDP Runtime.enable. Их расширенные сценарии ещё требуют переноса/починки;
обязательные Playwright-тесты не заменяют всё это покрытие. Интерактивный рабочий
стол Windows этим CI не проверяется. Успех локальных команд не подтверждает
работу workflow: для приёмки шага 4 нужны реальные красный/зелёный запуски
в тестовой ветке GitHub.

Уровень: браузерный E2E с настоящим HTTP-сервером, во втором сценарии
ошибка чтения моделируется перехватом запроса. Эти проверки не закрывают
всю QA-DOC-01: создание доски и повторное открытие относятся к шагу 3.
Источники ожиданий: [сценарии](../docs/product/02-scenarios.md),
[интерфейс](../docs/product/04-interface.md). Фактический прогон и окружение
фиксируются в [QA-плане](../docs/QA-PLAN.md); «прошло» не означает «принято».

QA-FLOW-001 (`e2e/planning.spec.mjs`) проверяет пункты 1–6 первого сквозного
сценария QA-плана: черновик/отмена сотрудника, релиз, дробные задачи A/B,
отпуск, отказ нулевой длительности, подтверждение записи и повторное открытие
после перезагрузки и перезапуска сервера. Дата фиксирована: 16.11.2026;
календарный API возвращает искусственную пятидневку без праздников.
Ожидания и ссылки на требования перечислены в протоколе шага 3 QA-плана.
Проверка включает интерфейс, память, HTTP-ответ записи и файл на диске.
Экспорт/импорт/восстановление относятся к последующему шагу 12.

| QA-DATE-003 | BR-CALENDAR-001 / EX-08, искусственный календарь                     | 20.11=1 (праздник), 21.11=2 (рабочая сокращённая суббота), вместе 1 рабочий день; выбор fallback отдельно по годам, невалидный календарь | unit/dates.test.mjs |

Сдвиг рабочих дней проверяется как смещение от первого допустимого дня:
ноль оставляет его на месте, единица переходит к следующему рабочему дню.
Это контракт вспомогательной функции, не новая нумерация дней для UI.
Распределение задач, отсутствие и загрузка относятся к шагу 7.
Неверные пользовательские строки дат проверяются на границе ввода в следующих
шагах; поведение низкоуровневого parseISO на таких строках здесь не утверждается.
Расширенная матрица часовых поясов и численный порог покрытия отложены [П].

Регрессии аудита A01–A08: `e2e/import-safety.spec.mjs`,
`e2e/audit-regressions.spec.mjs`, `unit/planning-contract.test.mjs`,
а также проверки HTTP-ошибок в `server-isolation.mjs` и закрытия вкладки
в `storage.mjs`. Браузерные сценарии проверяют импорт необычных ID,
доску больше 64 КБ, сохранение демо, повреждённые recovery-копии, даты
релиза, стили статусов и отказ неподдерживаемой длительности.
Редактирование задачи отдельно проверяет перенос в конец очереди другого
сотрудника, удаление ссылки и сохранение меток и метаданных обмена.

Настройка runner и coverage: [Vitest config](https://vitest.dev/config/),
[V8 coverage](https://vitest.dev/guide/coverage.html).
