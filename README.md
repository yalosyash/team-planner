# Планировщик загрузки команды

Доска распределения задач по сотрудникам отдела: **столбцы — люди, строки — дни релиза**.
Пишется под отдел тестирования (8–10 человек), но подходит любому отделу.

## Быстрый старт

1. Двойной клик по `start.bat` — запустится локальный сервер и откроется браузер.
   Консольного окна нет: сервер работает в фоне **и сам выключается, когда
   закрыта последняя вкладка планировщика**. Закрывать что-то вручную не нужно.
   Все данные **автоматически сохраняются в `data.json`** рядом с приложением.
   При первом запуске рядом появится ярлык **«Планировщик»** с иконкой —
   дальше удобнее запускать его, а не `start.bat`.
2. Либо откройте `index.html` напрямую. Тогда сервера нет, и данные хранятся
   в браузере (`localStorage`) — используйте кнопки Экспорт/Импорт.

Индикатор в правом верхнем углу показывает, куда идёт запись:
- **«Сохранено в data.json»** (зелёный) — работает сервер, данные на диске;
- **«Хранение: в браузере»** (красный) — сервер не запущен, данные застряли в браузере;
- **«Нет подключения — данные не сохранены»** (красная заливка) — сервер пропал:
  запись не удалась или он перестал отвечать на сигналы вкладки.

Если сервер пропал во время работы (упал, его закрыли, компьютер «уснул»),
индикатор сам краснеет в течение минуты — даже если правок не было. Когда
сервер снова оживёт (например, вы запустили `start.bat`), индикатор
вернётся в «Сохранено в data.json» сам.

Название команды указывается в шапке рядом с заголовком: нажмите **«Название команды»**,
впишите, например, «Тестирование» и нажмите Enter. Название сохраняется в данных
и попадает в заголовок вкладки браузера.

Интернет не нужен. Требуется только Node.js для режима с `data.json`
(Node v22 уже установлен; если его нет — `start.bat` откроет приложение
без сервера).

## Работа с приложением

### 1. Сотрудники
Кнопка **«Сотрудники»** в правом верхнем углу:
- добавление / удаление / переименование;
- цвет столбца — из готовой палитры (12 подобранных цветов, без «любого» цвета);
- порядок в списке = порядок столбцов на доске; строки переставляются
  перетаскиванием за ручку **⋮⋮** слева от имени.

Людей можно добавлять и удалять в любой момент.

### 2. Релиз
Кнопка **«+ Релиз»** справа от вкладок (как «+» в браузере):
- номер релиза — новый подставляется автоматически: последний числовой сегмент
  предыдущего увеличивается на 1 (`54.5 → 54.6`, `0.54 → 0.55`);
- дата начала и дата окончания;
- подтверждение.

Релизы открываются **вкладками** сверху, как вкладки в браузере. На вкладке:
- значок **✎** — редактировать номер и даты;
- значок **✕** — удалить релиз вместе с его задачами.

### 3. Задачи
Кнопка **«+ Задача»**:
- исполнитель (из списка сотрудников);
- дата начала работы — подставляется автоматически на первый свободный
  рабочий день этого человека от начала релиза; можно поправить вручную;
- время на задачу в **рабочих** днях с десятыми: `0.5` — полдня, `2` — два дня;
- галочка **«Работа в выходные»** — разрешает начать в субботу или воскресенье
  и считать дни календарными; у отпуска и больничного её нет, они всегда
  календарные;
- тип: Задача / Отпуск / Больничный;
- номер задачи (например, `TASK-1234`) и описание — до 500 символов, поле
  растёт по тексту и показывает счётчик.

Задачи считаются в **рабочих днях**: суббота и воскресенье пропускаются,
задача на 2 дня с пятницы займёт пятницу и понедельник. На доске такая задача
рисуется одним блоком, а выходные внутри него заштрихованы.

Отпуск и больничный считаются в календарных днях — они включают выходные.

После подтверждения в таблице появляется **плашка** под выбранным человеком,
растянутая от даты начала на количество дней.

### 4. Редактирование плашки
Клик по плашке открывает то же окно — можно поменять исполнителя, дату, дни,
тип и текст. При редактировании дата не переставляется автоматически.

### 5. Перенос задачи
Плашки по доске не перетаскиваются: чтобы поменять исполнителя или дату,
откройте плашку кликом и поправьте поля в окне задачи. Там же проверяется,
что задача не выходит за границы релиза и не начинается в выходной.

## Что показывает доска

- **Σ X дн** в шапке каждого человека — суммарная загрузка за релиз.
  Считаются все записи: задачи, отпуск и больничный.
- **Красная «Σ X дн»** — задач у человека больше, чем рабочих дней в релизе
  (пт → пн переносом учитываются только рабочие дни). Отпуск и больничный
  в это сравнение не входят, потому что считаются в календарных днях —
  их количество видно в подсказке при наведении на цифру.
- Дни с **перегрузкой** (больше 1 дня работы в сутки) подсвечиваются красным.
- **Выходные** (сб/вс) — серым фоном.
- Внутри длинной задачи выходные **заштрихованы** — видно, что работа в эти
  дни не идёт, хотя блок остаётся целым.
- Линия **«сегодня»** и подсвеченная строка с текущей датой в левой колонке
  (мягкий фон + синяя полоска).
- Если у человека задачи **пересекаются** по датам, они рисуются рядом
  (дорожками), а не наезжают друг на друга.
- **Отпуск** заливается жёлтым, **больничный** — красным.

## Данные

- **Автосохранение** — всё, что вы заводите, пишется в `data.json` (при запуске
  через `start.bat`). Запись идёт с задержкой ~0.5 с и атомарно (через `.tmp`),
  чтобы файл не побился при внезапном закрытии. Если закрыть вкладку сразу после
  правки, последнее изменение тоже дописывается — при закрытии вкладка
  отправляет данные без ожидания.
- **Версии (автобэкапы)** — сервер держит последние 20 версий в папке `backups/`.
  Снимок создаётся перед каждым изменением (не чаще раза в 15 сек) и при каждом
  запуске. Кнопка **«Версии»** в шапке показывает список с датами и позволяет
  **восстановить** любую — текущее состояние при этом тоже сохраняется.
  Это защита от случайного удаления задач, сотрудников или релиза.
- **Экспорт** — сохраняет всё в отдельный файл `team-planner-YYYY-MM-DD.json`
  (снимок / бэкап в другое место).
- **Импорт** — загружает данные из такого файла.
- `data.json` и `backups/` исключены из git (`.gitignore`) — это ваши рабочие данные.

Важно понимать: версии лежат **на том же диске**, поэтому спасают от случайных
изменений, но не от поломки диска. От этого — периодическая копия `data.json`
в облако / на флешку / в сетевую папку.

### Как проверить три состояния индикатора

Индикатор в правом верхнем углу — единственный признак того, что данные
действительно пишутся на диск. Проверка занимает пару минут:

1. **«Сохранено в data.json»** (зелёный) — запустите `start.bat`, дождитесь
   открытия браузера, сделайте любую правку (например, переименуйте команду).
   Индикатор должен остаться зелёным и снова показать «Сохранено в data.json».
   Дополнительно: в `data.json` рядом с приложением появится эта правка.
2. **«Хранение: в браузере»** (жёлтый/красный) — откройте `app/index.html`
   двойным кликом (`file://`), сервер при этом не запускайте. Данные живут
   в `localStorage` браузера; на диск ничего не пишется.
3. **«Нет подключения — данные не сохранены»** (сплошная красная заливка) —
   запустите `start.bat`, затем убейте процесс сервера:
   `Get-Process node | Stop-Process` (или включите в DevTools → Network →
   Offline) и сделайте правку. Индикатор должен покраснеть — сразу от
   неудачной записи, а если правок не было, то в течение минуты: вкладка
   раз в 30 секунд подаёт серверу сигнал, и две неудачи подряд переключают
   индикатор. Запустите `start.bat` снова — индикатор вернётся в зелёный сам.

Если какое-то из состояний не воспроизводится, значит, поменялось поведение
хранилища — это повод заглянуть в `app/js/store.js` (`setStatus()`)
и `app/js/keepalive.js` (сигнал вкладки и проверка связи).

## Структура

```
team-planner/
├── app/
│   ├── index.html    разметка страницы
│   ├── favicon.svg   значок вкладки браузера
│   ├── favicon.ico   тот же значок для старых браузеров (16 и 32 px)
│   ├── styles.css    стили
│   └── js/           логика, разбитая по смыслу
│       ├── utils.js      константы и вспомогательные функции (даты, формат, toast)
│       ├── store.js      состояние, сохранение/загрузка, автосохранение в data.json
│       ├── modals.js     общая механика модальных окон
│       ├── release.js    окно релиза: создание, редактирование, удаление
│       ├── task.js       окно задачи: создание, редактирование, удаление
│       ├── people.js     окно сотрудников
│       ├── tabs.js       вкладки релизов
│       ├── board.js      отрисовка доски
│       ├── data-io.js    экспорт, импорт, версии данных (автобэкапы)
│       ├── keepalive.js  сигнал «вкладка открыта» и проверка связи с сервером
│       ├── demo.js       демонстрационные данные
│       └── main.js       запуск приложения и верхняя панель
├── data/             ЛИЧНЫЕ ДАННЫЕ — в git не попадают (создаётся автоматически)
│   ├── data.json     ваши данные
│   ├── backups/      версии данных для отката
│   └── server.log    журнал фонового сервера (нужен только для разбора проблем)
├── server.js         локальный сервер: отдаёт app/ и пишет data/
├── start.bat         запуск: поднимает server.js без окна и открывает браузер
├── start-hidden.vbs  запускает сервер полностью скрыто (вызывается из start.bat)
├── create-shortcut.vbs  создаёт ярлык «Планировщик» с иконкой при первом запуске
├── .githooks/        защита от коммита личных данных
├── .gitignore
├── TODO.md           список доработок с оценками
└── README.md
```

Порядок подключения скриптов в `index.html` важен: `utils` → `store` → окна → `board`/`data-io` → `keepalive` → `demo` → `main`.

Код (`app/`), сервер и документация — публичная часть. Всё личное лежит в
`data/` и исключено из git. Сервер отдаёт по HTTP только содержимое `app/`,
поэтому файлы из `data/` недоступны даже по прямой ссылке в браузере.

## Защита личных данных

- Папка `data/` целиком в `.gitignore`.
- Хук `.githooks/pre-commit` **отклоняет коммит**, если в него попали
  `data/`, `backups/`, экспорты или файлы секретов (`.env`, `*.key`, `*.pem`).
  Включён через `git config core.hooksPath .githooks`.
- Проверить, что ничего лишнего не отслеживается:
  ```
  git ls-files
  ```
  Здесь должны быть только `app/`, `server.js`, `start.bat`, `start-hidden.vbs`,
  `create-shortcut.vbs`, `.gitignore`, `.githooks/`, `README.md` и `TODO.md` —
  никаких `data.json`.
