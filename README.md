# Планировщик загрузки команды

Доска распределения задач по сотрудникам отдела: **столбцы — люди, строки — дни релиза**.
Пишется под отдел тестирования (8–10 человек), но подходит любому отделу.

## Быстрый старт

1. Двойной клик по `start.bat` — запустится локальный сервер и откроется браузер.
   Все данные **автоматически сохраняются в `data.json`** рядом с приложением.
2. Либо откройте `index.html` напрямую. Тогда сервера нет, и данные хранятся
   в браузере (`localStorage`) — используйте кнопки Экспорт/Импорт.

Индикатор в правом верхнем углу показывает, куда идёт запись:
- **«Сохранено в data.json»** — работает сервер, данные на диске;
- **«Хранение: в браузере»** — сервер не запущен.

Интернет не нужен. Требуется только Node.js для режима с `data.json`
(Node v22 уже установлен; если его нет — `start.bat` откроет приложение
без сервера).

## Работа с приложением

### 1. Сотрудники
Кнопка **«Сотрудники»** в правом верхнем углу:
- добавление / удаление / переименование;
- цвет столбца;
- порядок в списке = порядок столбцов на доске.

Людей можно добавлять и удалять в любой момент.

### 2. Релиз
Кнопка **«+ Релиз»** справа от вкладок (как «+» в браузере):
- номер релиза;
- дата начала и дата окончания;
- подтверждение.

Релизы открываются **вкладками** сверху, как вкладки в браузере. На вкладке:
- значок **✎** — редактировать номер и даты;
- значок **✕** — удалить релиз вместе с его задачами.

### 3. Задачи
Кнопка **«+ Задача»**:
- исполнитель (из списка сотрудников);
- дата начала работы (в рамках релиза);
- время на задачу в днях с десятыми: `0.5` — полдня, `2` — два дня;
- тип: Задача / Отпуск / Больничный;
- номер задачи (например, `SPEKTR-1234`) и описание.

После подтверждения в таблице появляется **плашка** под выбранным человеком,
растянутая от даты начала на количество дней.

### 4. Редактирование плашки
Клик по плашке открывает то же окно — можно поменять исполнителя, дату, дни,
тип и текст.

### 5. Перетаскивание
Плашку можно тащить мышью на другого человека и/или на другую дату. Если задача
не влезает в границы релиза — приложение не даст её отпустить.

## Что показывает доска

- **Σ X дн** в шапке каждого человека — суммарная загрузка за релиз.
- Дни с **перегрузкой** (больше 1 дня работы в сутки) подсвечиваются красным.
- **Выходные** (сб/вс) — серым фоном.
- Линия **«сегодня»**.
- Если у человека задачи **пересекаются** по датам, они рисуются рядом
  (дорожками), а не наезжают друг на друга.
- **Отпуск** заливается жёлтым, **больничный** — красным.

## Данные

- **Автосохранение** — всё, что вы заводите, пишется в `data.json` (при запуске
  через `start.bat`). Запись идёт с задержкой ~0.5 с и атомарно (через `.tmp`),
  чтобы файл не побился при внезапном закрытии.
- **Экспорт** — сохраняет всё в отдельный файл `team-planner-YYYY-MM-DD.json`
  (снимок / бэкап).
- **Импорт** — загружает данные из такого файла.
- `data.json` исключён из git (`.gitignore`) — это ваши рабочие данные.

Резервные копии: достаточно периодически копировать `data.json`.

## Структура

```
team-planner/
├── index.html   приложение (весь интерфейс и логика в одном файле)
├── server.js    локальный сервер: отдаёт index.html и хранит data.json
├── start.bat    запуск: поднимает server.js и открывает браузер
├── data.json    ваши данные (создаётся автоматически, в git не попадает)
└── README.md
```

## Что можно добавить дальше

- отдельные оценки FE / BE в плашке (как `2 дня (0.5 FE и 1.5 BE)`);
- выгрузка в Excel / PDF;
- просмотр по месяцам отдельно от релиза;
- роли и права (кто что редактирует).
