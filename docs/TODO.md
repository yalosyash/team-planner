## 2. Праздничные и рабочие дни

Цель: учитывать праздники и переносы рабочих дней, чтобы обычные задачи
автоматически пропускали нерабочие дни.

Сейчас задачи выстраиваются очередью с начала релиза, пропуская субботу,
воскресенье и отсутствие сотрудника. Добавление праздничного дня должно
пересчитывать очередь и сдвигать следующие задачи.

Принятые решения:

- Использовать производственный календарь РФ.
- Календарь общий для приложения: одна и та же дата имеет одинаковый статус
  во всех релизах, включая частично пересекающиеся периоды.
- Сейчас в проекте учитываются только субботы и воскресенья. Производственный
  календарь РФ, праздники и переносы пока не подключены.

Реализовано 7 ноября 2026. Ручные поправки исключены по решению пользователя.

- [x] Общий производственный календарь РФ из isdayoff.ru: автозагрузка при запуске
      текущего года и лет релизов/задач, включая выход за конец релиза.
- [x] Единый календарь для очередей, штриховки, ёмкости и предупреждений.
- [x] Пересчёт задач всех релизов при загрузке календаря.
- [x] Отпуска и больничные в календарных днях.
- [x] «Работа в нерабочие дни» у задачи разрешает работу в праздники.
- [x] Локальное хранение загруженных лет в данных приложения, полном
      экспорте/импорте и резервных копиях.
- [x] При недоступности API сохранённые данные продолжают действовать.

Отдельной кнопки календаря нет. Новые годы подгружаются при изменении релизов
и задач. При восстановлении сети запросы повторяются. Для незагруженного года
действует пятидневка с видимым предупреждением. Сокращённый день считается полным.
При переносе отдельного релиза календарь не передаётся (см. пункт 3).

Проверено: реальный ответ API за 2026 год и node tests/calendar.mjs:
праздник, рабочая суббота, дробные задачи, отсутствия, пересчёт двух релизов,
предпросмотр, выход за конец, JSON-перенос и проверка формата.
Автозагрузка проверена в node tests/calendar-auto.mjs: несколько лет, кэш,
ошибки сети, старый сервер и отсутствие повторных запросов при перерисовке.
Новый серверный маршрут проверен реальным запросом к isdayoff.ru.

## 3. Экспорт и импорт отдельного релиза

Реализовано 7 ноября 2026: передача тимлид → замещающий → тимлид.

Согласованные решения:

- Передавать только сотрудников с задачами, включая отпуска и больничные.
- При первом импорте вручную сопоставлять сотрудника с существующим или
  добавлять нового. Совпадение имени — только подсказка; связь запоминается
  для следующих передач этого релиза.
- Календарь не передавать. Каждый использует свой производственный календарь.
- При параллельных правках показывать конфликт; замена целиком — только после
  явного подтверждения и резервной копии. Объединение отдельных задач не входит
  в первую версию.
