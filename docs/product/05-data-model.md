строго проверяет документ, импорт предварительно выбирает известные поля.

## DM-BOARD-001. Доска и связи

| Поле доски v4 | Тип / начальное значение | Назначение                                                                    |
| ------------- | ------------------------ | ----------------------------------------------------------------------------- |
| version       | число, `4`               | Версия формата доски                                                          |
| team          | строка, `""`             | Название команды                                                              |
| people        | массив, `[]`             | Общие сотрудники, порядок равен порядку столбцов                              |
| releases      | массив, `[]`             | Релизы в порядке вкладок; новые добавляются в конец                           |
| tasks         | массив, `[]`             | Задачи и отсутствия; порядок задаёт очередь для каждой пары исполнитель/релиз |

Все пять полей обязательны. Лишние поля прямого документа отвергаются.
Каждый id — непустая строка длиной до 200; уникальность проверяется внутри
каждой коллекции, а не одновременно между людьми, релизами и задачами.
`task.personId` и `task.releaseId` должны ссылаться на существующие элементы.
Одинаковые имена сотрудников и номера релизов допускаются.
Поля `exchange.people` и снимков проверяются своим контрактом; не следует
приписывать им все проверки внешних ключей основной коллекции `tasks`.

## DM-PERSON-001. Сотрудник

| Поле  | Тип / создание через UI                       | Проверка документа                       |
| ----- | --------------------------------------------- | ---------------------------------------- |
| id    | строка от `uid()`                             | Обязательный уникальный id               |
| name  | строка, `Новый сотрудник`                     | Обязательная строка, пустая допустима    |
| color | строка, очередной цвет PALETTE по числу людей | Обязательный `#RRGGBB`, регистр не важен |

Окно сотрудников редактирует отдельную копию people. Только «Готово» заменяет
список в доске и удаляет записи исключённых сотрудников. Закрытие без применения
отбрасывает черновик. Ввод имени сохраняет исходную строку без trim.
Пустое имя на доске/в выборе исполнителя заменяется подписью «Без имени».
Цвет относится к сотруднику, поэтому меняет его оформление во всех релизах.
Перестановка меняет `people`, не очередь `tasks`.
Удаление человека удаляет все его записи во всех релизах, не сами релизы.
Основание: `features/people.js`, `ui/palette.js`, `ui/board.js`.

## DM-RELEASE-001. Релиз

| Поле     | Тип / создание через UI          | Проверка документа                           |
| -------- | -------------------------------- | -------------------------------------------- |
| id       | строка от `uid()`                | Обязательный уникальный id                   |
| number   | строка, сначала `1.0`            | Обязательная строка с непустым trim          |
| start    | дата YYYY-MM-DD, сегодня         | Реальная дата 1900–2100                      |
| end      | дата, start + 9 календарных дней | Не раньше start; разница не больше 366 суток |
| exchange | необязательный объект            | Метаданные передачи, см. DM-EXCHANGE-001     |

Следующий номер берётся из последнего элемента `releases`: увеличивается
последний целиком числовой сегмент, ширина ведущих нулей сохраняется.
Примеры из алгоритма: `0.054 → 0.055`, `RC → RC.1`.
Правка дат не меняет id и связи; обычные задачи перепаковываются,
даты отсутствий не переносятся автоматически. Удаление удаляет все записи
релиза. Если он выбран, выбирается последний оставшийся, иначе `null`.
Основание: `features/release.js`, `core/render.js`, `core/plan.js`.

## DM-TASK-001. Задача и отсутствие

| Поле       | Тип / обязательность в v4                                           | Значение при создании обычной задачи                                                           |
| ---------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| id         | строка, обязательно и уникально                                     | `uid()`                                                                                        |
| releaseId  | строка, обязательно                                                 | id выбранного релиза                                                                           |
| personId   | строка, обязательно                                                 | Первый сотрудник в списке, затем выбор пользователя                                            |
| start      | реальная дата 1900–2100, обязательно                                | Изначально начало релиза, затем результат очереди                                              |
| days       | конечное число 0.01–2000, до двух знаков после запятой, обязательно | `1`; кратность 0.5 не требуется; очередь должна помещаться в горизонт расчёта, см. BR-PLAN-002 |
| type       | task/vacation/sick, обязательно                                     | `task`                                                                                         |
| labels     | массив уникальных FE/BE, обязательно                                | `[]`, UI позволяет обе независимо                                                              |
| weekend    | boolean, обязательно                                                | `false`                                                                                        |
| daysMode   | строка, обязательно                                                 | Только `work` в современном формате                                                            |
| number     | необязательная строка                                               | `""`                                                                                           |
| title      | необязательная строка                                               | Описание, `""`                                                                                 |
| status     | необязательная строка                                               | `""`; также waiting / preprod                                                                  |
| link       | необязательная строка                                               | При пустом вводе поля нет в JSON                                                               |
| exchangeId | необязательный id                                                   | Возникает при передаче/импорте                                                                 |

В UI `waiting` подписан «Не передано», `preprod` — «Готово».
У отсутствия пользователь задаёт start; UI записывает `weekend: true`,
`labels: []`, пустые number/title/status и удаляет link. `daysMode: work`
не делает отпуск рабочим: тип и weekend задают календарный режим.
Строгая схема требует у отсутствий weekend=true и пустые labels, но сама
не запрещает непустые title/number/допустимый status/link. Поэтому обещание
«таких полей никогда не бывает в файле отсутствия» было бы сильнее кода.

Правка сохраняет id/releaseId; смена исполнителя переносит запись в конец
общего массива (то есть в конец новой рабочей очереди, если тип task).
Смена типа при том же исполнителе сохраняет позицию массива. При превращении
задачи в отсутствие свойства обычной задачи очищаются; обратное переключение
не восстанавливает прежнее описание. В пределах ещё не применённого диалога
скрытые значения могут сохраняться до нажатия кнопки подтверждения.
Основание: `features/task.js: openTask, syncTaskType, saveTask`,
`core/task-labels.js`, `core/storage-schema.js: task`.

## DM-LOCAL-001. Локальные документы

| Документ       | Поля / начальные значения                                                                                                                | Связь с доской                                                                                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| preferences v1 | theme=light, activeId=null                                                                                                               | Тема light/dark и выбранный релиз; при загрузке/замене несуществующий выбор исправляется на первый релиз либо null |
| system v1      | calendar={years:{}}, launcher={desktopShortcutAsked:false, desktopShortcutCreated:false}, queueNotice=false, migrations={splitStorage:0} | Календарь, ответ о ярлыке, служебные отметки; это окружение установки                                              |

У записей `calendar.years[YYYY]` обязательно days — строка кодов 0/1/2
длиной 365/366, допустимы updatedAt (ISO-дата со временем) и source=isdayoff.ru.
У system допускаются дополнительные секции верхнего уровня; внутри известных
секций поля ограничены схемой. `splitStorage` равен 0 или 1.
Браузерный patch может менять calendar/queueNotice, launcher — секцию launcher.

В оперативном `state` theme/activeId/calendar/queueNotice доступны через
неперечисляемые свойства. Они не входят в JSON доски. Состояния backend,
readOnly, запросов, ревизий и recovery не являются полями сущностей доски.
Основание: `core/storage.js: attach, ensureActive, replaceState`,
`core/storage-schema.js: defaults, patchSystem`.

## DM-EXCHANGE-001. Связи передачи

`release.exchange` содержит обязательные origin (id происхождения), people
(пары local/remote, уникальные по каждой стороне), parents (уникальные id
передач). Необязательны base, sent, received и lastImport.
base — снимок release(number/start/end) и tasks; sent — до 20 записей
transferId/snapshot; received — уникальные id принятых передач;
lastImport — id последнего импорта. В снимках задач нет releaseId/exchangeId,
их id и personId относятся к пространству передачи.

Пакет v1 имеет format=`team-planner-release`, version=1, transferId, origin,
exportedAt, parents, base, release, tasks и people. Это транспортная структура,
а не четвёртый локальный документ. Экспорт добавляет exchangeId задачам,
связи людям и снимок передачи; поэтому экспорт релиза изменяет доску.
Импорт сохраняет локальный id распознанного релиза и существующие id задач
по exchangeId, новым выдаёт новые id; сохраняет соответствие людей.
Действия и конфликты — в [сценарии передачи](02-scenarios.md#uc-transfer-001-передать-один-релиз-и-принять-возврат),
сохранность — в [хранении и обмене](06-storage-and-exchange.md).
Основание: `core/release-transfer.js: snapshot, exportRelease, validatePacket,
applyRelease`, `core/storage-schema.js: exchange, snapshot`.

## DM-MIGRATION-001. Версии и производные значения

`workingData` принимает версии доски 1–4 (без version — 1), выбирает рабочие
поля, дополняет отсутствующие type/weekend/labels и строковые поля,
выполняет `migrateTasks`, затем валидирует v4. Неверная известная модель
daysMode отклоняется. Современный `daysMode: work` сохраняет порядок;
старые группы обычных задач сортируются по прежней дате start и переводятся
из календарной длительности с пропуском сб/вс. Отсутствия сохраняют длительность.
Копии и повтор переноса — в [описании миграции](06-storage-and-exchange.md#st-migrate-001--переход-старой-установки), точный состав документов — в [контракте](#dm-contract-001-состав-json-документов).

Очередь, сегменты по дням, absent, загрузка, дни за релизом, геометрия и
подсказки вычисляются, отдельными сущностями не сохраняются. Исключение:
рассчитанный start обычной задачи записывается обратно перед отрисовкой.
Основание: `core/task-migration.js`, `core/plan.js`, `core/render.js`.

## DM-CONTRACT-001. Состав JSON-документов

Форматы — UTF-8 JSON. Версии: доска 4, preferences 1, system 1;
версия формата отличается от ревизии записи SHA-256. Пустые документы:

```json
{ "version": 4, "team": "", "people": [], "releases": [], "tasks": [] }
```

```json
{ "version": 1, "theme": "light", "activeId": null }
```

```json
{
  "version": 1,
  "calendar": { "years": {} },
  "launcher": {
    "desktopShortcutAsked": false,
    "desktopShortcutCreated": false
  },
  "queueNotice": false,
  "migrations": { "splitStorage": 0 }
}
```

Рабочая доска и её вложенные объекты используют явные списки полей:

| Объект                     | Поля                                                                                                                                                      |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Корень                     | `version`, `team`, `people`, `releases`, `tasks`                                                                                                          |
| Сотрудник                  | `id`, `name`, `color`                                                                                                                                     |
| Релиз                      | `id`, `number`, `start`, `end`, необязательный `exchange`                                                                                                 |
| Задача                     | `id`, `releaseId`, `personId`, `start`, `days`, `type`, `number`, `title`, `status`, `link`, `labels`, `weekend`, `daysMode`, необязательный `exchangeId` |
| `exchange`                 | `origin`, `people`, `parents`, `base`, `sent`, `received`, `lastImport`                                                                                   |
| Элемент `exchange.people`  | `local`, `remote`                                                                                                                                         |
| Элемент `exchange.sent`    | `transferId`, `snapshot`                                                                                                                                  |
| Снимок `base` / `snapshot` | `release`, `tasks`                                                                                                                                        |
| Релиз внутри снимка        | `number`, `start`, `end`                                                                                                                                  |
| Задача внутри снимка       | поля задачи без `exchangeId` и `releaseId`; `id` и `personId` относятся к пространству обмена                                                             |

Снимки очищаются рекурсивно; произвольные вложенные свойства не попадают
в экспорт через копирование объекта. Неизвестные поля старой доски остаются
в точной миграционной копии. Неверное известное поле прерывает миграцию,
а не приводит к молчаливому удалению сущности. Система допускает неизвестные
секции верхнего уровня; известные секции проверяются по схеме.

У calendar.years допустимы годы 1900–2100. Метаданные старого валидного года
необязательны: время загрузки не подставляется задним числом.
Оба флага launcher — boolean: desktopShortcutAsked фиксирует ответ, включая
отказ; desktopShortcutCreated — результат создания, а не текущее наличие ярлыка.
queueNotice — служебный boolean, не команда интерфейса. Маркер splitStorage=1
ставится после завершения переноса и не заменяет проверку документов.

Более новая неизвестная версия и повреждённый существующий документ
не заменяются дефолтами. Отсутствующий документ и повреждённый различаются.
Проверки полей — в разделах DM-BOARD/PERSON/RELEASE/TASK/LOCAL/EXCHANGE выше;
порядок переноса — [ST-MIGRATE-001](06-storage-and-exchange.md#st-migrate-001--переход-старой-установки).
Основание: core/storage-schema.js, core/storage-migration.js,
core/release-transfer.js; сведения перенесены из прежнего контракта хранения.
