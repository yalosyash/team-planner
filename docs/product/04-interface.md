# Интерфейс: действия и проверки полей

Срез этапа 2: [ревизия, метод и словарь](01-overview.md).
Здесь описаны экран, действия, ввод и отображение доски. Механизмы хранения,
сетевые ошибки и жизненный цикл описаны в разделах06–08. Проверенные
в браузере действия и пределы проверки — в [протоколе](../PRODUCT-DOCS-CHECKS.md).
Источники: `app/index.html`, модули `app/js/features/`, `app/js/ui/`,
`app/js/core/storage-schema.js`; названия ниже сверены с разметкой/обработчиками.

## UI-SCREEN-001. Что видно после открытия

После перехода на локальный адрес, открытый `start.bat`, приложение загружает
данные. Сверху находится название приложения и команды, индикатор хранения,
кнопка темы, «Сотрудники», «+ Задача», «Экспорт», «Импорт» и «Меню».
Под шапкой — вкладки релизов с номером, датами, карандашом и крестиком,
в конце — кнопка с плюсом. Ниже располагается основная область доски.

| Что загружено                          | Что видно в основной области                                                        | Действие → реакция                                                                              |
| -------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Нет сотрудников                        | «Добавьте сотрудников», пояснение, «Добавить сотрудников», «Загрузить демо»         | «Добавить сотрудников» открывает «Сотрудники отдела»; демо сразу создаёт демонстрационную доску |
| Сотрудники есть, выбранного релиза нет | «Создайте релиз», пояснение, «+ Новый релиз»                                        | Кнопка открывает «Новый релиз» с номером и датами                                               |
| Есть сотрудники и выбранный релиз      | Слева даты, справа столбцы людей; в шапках имена и Σ, внутри карточки               | Клик вкладки меняет видимый релиз; клик карточки открывает её редактирование                    |
| Ошибка начальной загрузки              | «Не удалось загрузить данные: …», элементы ввода отключены                          | Изменение данных недоступно; дальнейшие действия зависят от текста ошибки                       |
| Браузерный режим только чтения         | Индикатор «Только чтение и экспорт: нет Web Locks / Web Crypto», редактор ограничен | Доступен полный экспорт; редактирование доски недоступно                                        |

Наличие панели не означает, что загрузка уже завершилась. Отсутствие карточек
в заполненной сетке означает, что видимых записей нет; это отличается от
отсутствия сотрудников или релиза. Основание: `app/index.html`,
`app/main.js`, `ui/board.js: renderBoard`, `core/storage.js: initStorage`.

## UI-BOARD-001. Как читать доску и открывать записи

| Видимый элемент                              | Как с ним взаимодействовать                      | Что получается                                                                                         |
| -------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Дата слева, порядковый день релиза           | Смотреть строку напротив нужного сотрудника      | Видно календарное положение карточки; строка даты не создаёт запись кликом                             |
| Серый фон нерабочих дат                      | Сравнить с режимом задачи                        | Обычная задача пропускает день; разрешённая работа может занимать его                                  |
| Синяя строка/линия «сегодня»                 | Найти текущую дату внутри релиза                 | Линия проходит через доску; вне периода отметки нет                                                    |
| Имя и Σ в шапке                              | Навести на показатель Σ                          | Подсказка объясняет длительность задач, норму и отсутствия; красный Σ означает превышение полной нормы |
| «+N дн за релизом»                           | Навести на показатель, найти пунктирную карточку | Видно объём работы после конца периода; это отдельный показатель от красного Σ                         |
| Обычная карточка                             | Нажать вне ссылки                                | Откроется «Редактирование задачи» с её значениями                                                      |
| Номер карточки со ссылкой                    | Нажать номер                                     | Откроется адрес в новой вкладке; диалог правки не открывается                                          |
| Обрезанный текст или очень короткая карточка | Навести указатель                                | Пользовательская подсказка показывает содержимое; целиком не вместившиеся задачи получают её всегда    |
| «!» / «✓»                                    | Навести на значок                                | Подсказка «Не передано» / «Готово»; статус не освобождает время в очереди                              |
| FE / BE перед номером                        | Прочитать метки; менять через диалог карточки    | Обе метки независимы, сами не меняют даты и загрузку                                                   |
| Штриховка внутри длинной задачи              | Сопоставить с нерабочими днями и отсутствием     | Карточка остаётся цельной, работа в этих промежутках не расходуется                                    |
| Отпуск/больничный поверх работы              | Нажать карточку отсутствия                       | Откроется редактирование с типом, исполнителем, датой и длительностью                                  |
| Пунктирная карточка у конца                  | Нажать её                                        | Можно изменить работу, не вместившуюся в релиз; её полная длительность сохранена                       |

Карточки не перетаскиваются. Для смены исполнителя нужно открыть карточку
и выбрать человека. Две задачи по полдня могут занимать верхнюю и нижнюю
половины одной строки. Целиком вышедшая работа показывается условной
карточкой последнего дня, которая не добавляет рабочую загрузку этому дню.
Отсутствие целиком вне периода не получает такую карточку.
Полные [правила и примеры](03-business-rules.md).

Техническое основание: `ui/board.js: renderDates, renderHeads, renderBodies,
renderCards, cardHTML, bindCards, applyHints`, `ui/tooltip.js`,
`app/css/board.css`. Описано по коду; размещение подсказок и видимость
в реальном браузере не проверены; выполненный срез — в [протоколе](../PRODUCT-DOCS-CHECKS.md).

## UI-VALID-001. Поля и уровни проверки

У кнопок диалогов нет отправки HTML-формы с `reportValidity()`.
Атрибуты min/max/step/maxlength влияют на браузерный ввод, но не заменяют
проверку обработчика. При сохранении клиент валидирует три документа;
сервер использует ту же схему. Ошибка схемы может появиться уже после
закрытия диалога, в индикаторе сохранения. Текст схемы: «Неверное поле: …».

| Поле                   | UI и обработчик                                                                                                                          | Схема документа                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Название команды       | maxlength=40; trim при применении; пусто допустимо                                                                                       | Строка, без лимита 40                                                                                                   |
| Имя сотрудника         | Без required/maxlength; input меняет черновик, «Готово» применяет, без trim                                                              | Строка, пусто допустимо                                                                                                 |
| Цвет                   | Выбор из палитры; прежний нестандартный цвет также показывается                                                                          | Шесть hex-цифр после #                                                                                                  |
| Номер релиза           | trim; пусто → «Укажите номер релиза»                                                                                                     | Непустой trim; уникальность номера не требуется                                                                         |
| Даты релиза            | Пусто → «Укажите обе даты»; конец раньше → «Дата окончания раньше даты начала»; разница >366 → «Слишком длинный период (макс. 366 дней)» | Реальные даты 1900–2100, конец ≥ начало, разница ≤366; включительный период может иметь 367 дат, см. Q-08               |
| Исполнитель            | select по текущим людям; пусто → «Выберите исполнителя»                                                                                  | Существующий personId; одновременно нужен существующий releaseId                                                        |
| Тип                    | «Задача», «Отпуск», «Больничный»                                                                                                         | task/vacation/sick                                                                                                      |
| Рабочих дней / Дней    | number, min=0.5, step=0.5, начально 1; обработчик проверяет документ-кандидат до изменения доски                                         | Конечное число 0.01–2000, до сотых; кратность 0.5 не требуется; превышение горизонта 2000 календарных шагов даёт ошибку |
| Дата начала            | Только у отсутствия; начально начало релиза, min/max по релизу; пусто → «Укажите дату начала»                                            | Реальная дата 1900–2100; попадание в релиз не проверяется схемой                                                        |
| Номер задачи           | Необязателен, trim                                                                                                                       | Необязательная строка, уникальность не требуется                                                                        |
| Ссылка                 | maxlength=500, trim и normalizeLink; без схемы добавляется https; ошибка → «Ссылка может быть только http:// или https://»               | Строка, непустая должна разбираться normalizeLink; лимит 500 схемой не задан                                            |
| Описание               | textarea maxlength=500, счётчик, явное обрезание на input и при save, trim                                                               | Необязательная строка, лимит 500 схемой не задан                                                                        |
| Статус                 | «Обычная», «Не передано», «Готово»; начально обычная                                                                                     | Пусто/отсутствует, waiting, preprod                                                                                     |
| Метки                  | Независимые FE и BE; начально ни одной                                                                                                   | Уникальные элементы FE/BE; у отсутствия пустой массив                                                                   |
| Работа в нерабочие дни | Чекбокс обычной задачи, начально снят                                                                                                    | boolean weekend; у отсутствия обязательно true                                                                          |

У отсутствий скрыты номер, ссылка, описание, статус, метки и checkbox weekend.
При применении скрытые свойства очищаются, weekend записывается true.
У обычной задачи нет редактируемой даты начала. Для неё дополнительно
проверяется непустая раскладка: «Задача не занимает ни одного дня».
Основание: `features/task.js: openTask, syncTaskType, saveTask`,
`features/release.js: saveRelease`, `ui/team.js: edit`, `features/people.js: bindRow`.

## UI-CANCEL-001. Закрытие и отмена

Обычные диалоги закрываются «Отмена»/крестиком/кликом по фону/Escape.
Для задачи и релиза ввод до применения не меняет сущность. При открытой
палитре первый клик по фону закрывает палитру; Escape перехватывается ею.
В окне сотрудников имя, цвет, порядок, добавление и удаление меняют черновик.
«Готово» применяет его; крестик, фон и Escape отменяют все правки окна.
Отмена browser confirm оставляет сотрудника в списке. Закрытие окна импорта не откатывает уже применённый импорт.
Если закрыть предпросмотр релиза во время резервирования, `applyPending`
проверяет, осталось ли окно открытым, прежде чем заменить доску.

После изменения имени нажмите «Готово»: окно закроется, шапка доски покажет
новое имя. При закрытии крестиком, фоном или Escape останется прежнее имя.
Основание: `ui/modal.js`, `ui/palette.js`, `features/people.js: initPeople`,
`features/release-transfer.js: applyPending`.

## UI-IO-001. Ввод файлов и ошибки

Полный импорт ограничивает выбранный файл 5 МиБ, релиз — 10 МиБ.
Это клиентские ограничения файла, не обещание успешного сохранения такого
размера: серверные операции имеют [собственные лимиты](07-architecture-and-api.md).
Полный импорт сразу проверяет JSON/workingData и резервирует память;
отдельного confirm замены всей доски в обработчике нет.
Ошибка выводится как «Не удалось загрузить данные: …».
Импорт релиза сначала показывает предпросмотр; ошибки чтения —
«Не удалось загрузить релиз: …», ошибки применения — внутри `riError`.
Замена релиза требует галочки; повторный пакет блокируется.
Для каждого человека нужен выбор; нельзя сопоставить двух разных людей
одному существующему сотруднику. Пустой выбор/дубликат отклоняются до копии.
Основание: `features/data-io.js`, `features/release-transfer.js`,
`core/release-transfer.js: applyRelease`.

## UI-SETTINGS-001. Тема и обновления

| Что открыто                    | Действие                               | Что появляется/меняется                                         | Как проверить результат                                                                         |
| ------------------------------ | -------------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Основной экран в светлой теме  | Нажать луну с подсказкой «Тёмная тема» | Применяется тёмное оформление, кнопка предлагает «Светлая тема» | Тема меняется сразу, личная настройка сохраняется                                               |
| Основной экран в тёмной теме   | Нажать солнце                          | Светлая тема; кнопка предлагает тёмную                          | Записи доски остаются, меняется оформление                                                      |
| Основной экран                 | «Меню»                                 | Меню с копиями, проверкой обновлений и строкой версии           | Можно прочитать установленную версию                                                            |
| Меню без найденного обновления | «Проверить обновления»                 | «Проверка обновлений…», кнопка временно недоступна              | Дождаться сообщения о версии либо «Не удалось проверить обновления. Попробуйте ещё раз.»        |
| Найдена новая версия           | Открыть «Меню» по синей точке          | Пункт «Доступна версия …»                                       | Нажатие открывает страницу релизов в новой вкладке, само приложение не устанавливает обновление |

Обновления также проверяются автоматически; отсутствие точки не доказывает,
что проверка успешно прошла. Тема применяется до загрузки страницы из кэша,
затем синхронизируется с настройками. Основание: `core/theme.js`,
`init/theme-boot.js`, `features/updates.js`. Проверка обновлений через настоящую
сеть и визуальная проверка темы в этой работе не выполнялись.
