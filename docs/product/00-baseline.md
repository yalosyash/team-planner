## Границы продукта

Планировщик показывает сотрудников столбцами, календарные дни выбранного
релиза строками. Пользователь ведёт общую команду, релизы, очереди задач
и отсутствия. Название команды задаётся в шапке. Исполнитель и свойства
задачи меняются в диалоге; перемещение карточек мышью не реализовано.
Порядок сотрудников можно менять перетаскиванием в списке сотрудников.

Основной путь — `start.bat`, Node.js и локальный HTTP-сервер на Windows.
Предусмотрен браузерный backend при ответе 404 на `/api/health`;
прямое открытие HTML с диска показывает инструкцию запуска, поэтому его
нельзя считать штатным способом использования браузерного backend.
При отсутствии Web Locks / Web Crypto браузерное хранилище допускает
чтение и полный экспорт; редактор ограничивается в `app/main.js`.

Доска, личные настройки и системные настройки хранятся отдельно.
Есть полный обмен JSON, передача одного релиза с сопоставлением людей,
резервные копии и миграции прежних форматов. Конкурирующие записи проверяют
ревизию; автоматическое объединение досок не заявлено.
Проверка обновлений ведёт на страницу релизов, установка обновления вручную.
Календарь и проверка обновлений обращаются во внешнюю сеть; основной редактор
может работать без неё с доступным локальным сервером.

В просмотренной реализации нет пользовательских аккаунтов, разграничения
ролей, совместного сетевого редактора, автоматической установки обновлений,
массового выбора карточек и команды ручного изменения очереди задач.
Сохраняемый порядок массива задач не означает наличие редактора очереди.
Это границы текущего кода, а не запрет на развитие продукта.
