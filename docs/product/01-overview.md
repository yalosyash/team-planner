# Назначение и словарь

Срез этапа 2 от 10.11.2026, код commit

документацию этапов 1–2, изменений приложения нет. Выводы получены чтением
кода; ручная проверка сценариев относится к этапу 5.
[Границы продукта и источники](00-baseline.md).

Team Planner помогает распределять работу команды по релизам и сотрудникам,
учитывать отсутствия и видеть загрузку. Сотрудники общие для всех релизов.
На доске одновременно виден один выбранный релиз.

| Термин          | Значение для пользователя                                                                           | Представление в коде                                                           |
| --------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Команда         | Название общей доски и список людей; отдельные команды внутри файла не создаются                    | `data.team`, `data.people`                                                     |
| Сотрудник       | Исполнитель, которому соответствует столбец во всех релизах                                         | Элемент `people` с собственным id, именем и цветом                             |
| Релиз           | Период с номером, отдельная вкладка и набор записей                                                 | Элемент `releases`; номер не является идентификатором                          |
| Задача          | Работа с длительностью, исполнителем, необязательными номером, описанием, ссылкой, статусом и FE/BE | Запись `tasks` с `type: task`                                                  |
| Отсутствие      | Отпуск или больничный на собственной дате; вводится через окно задачи                               | Та же коллекция `tasks`, тип `vacation` или `sick`                             |
| Очередь         | Последовательность обычных задач одного сотрудника в одном релизе                                   | Порядок соответствующих элементов в `tasks`; отдельного массива очередей нет   |
| Начало задачи   | Рассчитанная дата первого участка работы, не вводится для обычной задачи                            | `task.start` обновляется перед отрисовкой; у отсутствия это входная дата       |
| Рабочий день    | День по загруженному производственному календарю, иначе по пятидневке                               | `calendarWorkday`; сокращённый день остаётся целым рабочим днём                |
| Загрузка        | Рабочая длительность, размещённая в дне; в шапке также выводится сумма длительностей записей        | `personLoad`, `renderHeads`; это разные показатели                             |
| Перегрузка      | Выделение превышения нормы в шапке или работы за день на доске                                      | Формулы и граничные примеры — этап 3                                           |
| За релизом      | Работа, которую очередь разместила после конца периода                                              | Раскладка сохраняет участки за границей; видимая карточка обрезается           |
| Выбранный релиз | Вкладка, которую сейчас показывает доска                                                            | `preferences.activeId`, личная настройка                                       |
| Резервная копия | Снимок доски для восстановления; настройки окружения не заменяет                                    | Серверные backups или одна браузерная копия перед заменой                      |
| Передача релиза | JSON одного релиза с людьми, записями и связями для возврата                                        | Пакет `team-planner-release` v1; отличается от полного экспорта                |
| Сохранение      | Запись изменения из памяти в выбранное хранилище                                                    | Отложенный `save()` и `persist()`; закрытие окна задачи не подтверждает запись |

Основание: `core/storage-schema.js`, `core/storage.js`, `core/plan.js`,
`core/calendar.js`, `ui/board.js`, `core/release-transfer.js` в `app/js/`.
