## RUN-START-001 — открыть приложение

| Исходное состояние | Действие | Что появляется | Результат |
| --- | --- | --- | --- |
| Папка приложения | Дважды щёлкнуть `start.bat` | Короткое консольное окно; при первом запуске вопрос «Создать ярлык на рабочем столе?» | После подготовки сервер запускается скрыто, открывается браузер по loopback-адресу |
| Вопрос о ярлыке | Выбрать «Да» | На рабочем столе ярлык «Планировщик» с иконкой | Ярлык ведёт на start.bat; ответ сохраняется отдельно от доски |
| Тот же вопрос | Выбрать «Нет» (кнопка по умолчанию) | Запуск продолжается | Ответ запоминается; каждый запуск снова не спрашивает |
| Node отсутствует в PATH | Запустить BAT | «Node.js не найден…», инструкция установить LTS и пауза | Сервер не запускается |
| Ошибка подготовки/сохранения ответа о ярлыке | Запустить BAT | Сообщение об отмене и пауза | Скрытый сервер не запускается |
| Эта установка уже работает | Ещё раз запустить | Открывается адрес найденного экземпляра | Второй сервер для той же доски не создаётся штатной веткой поиска |

BAT переходит в каталог установки, находит первый `node` через `where`,
временно включает UTF-8 и восстанавливает кодовую страницу. Сначала
`cscript create-shortcut.vbs <node>` синхронно вызывает launcher, затем
`wscript start-hidden.vbs <node>` запускает `server.js --hidden` без ожидания
и без окна. Поэтому ошибка уже скрытого сервера видна в журнале, а не
обязательно в BAT. Существующий ярлык получает обновлённую иконку;
отказанный или удалённый после сохранённого ответа ярлык сам не создаётся повторно.

Launcher проверяет/готовит разделённое хранение и записывает только свою секцию
system под общей файловой блокировкой. Сервер ищет работающую установку через
health: совпасть должен абсолютный `dataFile`, а не только `ok:true`.
Поиск идёт по 11 портам от базового8787 до8797 с таймаутом800мс на запрос.
Если подходящего сервера нет, захватывается `runtime/instance.lock`, готовится
хранение и слушается `127.0.0.1`. При занятом порте пробуются следующие, максимум
10 переходов. Одновременный запуск дополнительно ограничивает instance.lock;
ошибка блокировки отменяет старт, а не гарантирует открытие второй вкладки.

Существующие PID проверяются до миграции; неизвестный/живой процесс автоматически
не завершается. При старте делается снимок существующей доски; его ошибка
отменяет запуск. PID нового сервера пишется в `runtime/server.pid`.

Для технического запуска поддержаны `node server.js`, `--hidden`, `--no-open`,
`--port=N` (целое0–65535,0 выбирает свободный порт ОС). Без hidden сообщения идут
в консоль и закрытие вкладок само по себе сервер не останавливает.

## RUN-TABS-001 — закрыть и открыть повторно

| Экран и действие | Реакция | Ожидаемый результат и граница |
| --- | --- | --- |
| Доска открыта | Вкладка сразу и раз в30с отправляет alive со своим sessionStorage ID | Скрытый сервер учитывает живую вкладку |
| Закрыть одну из нескольких вкладок | beforeunload/pagehide отправляют bye | Сервер остаётся, если ещё есть свежий сигнал другой вкладки |
| Закрыть последнюю вкладку | Проверка через10с после bye | Скрытый сервер завершается, если живых вкладок нет |
| Браузер упал без bye | Сигнал стареет более3мин, чистка каждые20с | Проверка через10с и дополнительная минута ожидания; точное время не гарантируется |
| Вкладка вернулась после сна или из back-forward cache | Новый API-запрос отменяет остановку; pageshow.persisted возобновляет ping | Вкладка получает возможность продолжить работу до окончательной остановки |
| Браузер так и не подключился после hidden-запуска | Страховочный таймер10мин | Если ни одной вкладки не было, сервер завершается |

Перед закрытием дождитесь «Сохранено»; связь закрытия и сохранности описана
в [ST-SAVE-001](06-storage-and-exchange.md#st-save-001--как-понять-что-изменения-сохранены).
Остановка сервера не заменяет подтверждение записи. При SIGINT/SIGTERM вызывается
shutdown: свой PID-файл удаляется при совпадении номера, сервер закрывается,
через1с есть принудительный выход. Instance.lock освобождается обработчиком exit;
аварийное убийство может оставить блокировку. После обычного повторного запуска
доска читается из сохранённых документов, вкладка релиза — из preferences.

## RUN-DIAG-001 — что делать при проблеме

| Что пользователь видит | Действие | Что проверить / результат |
| --- | --- | --- |
| После BAT нет страницы | Проверить `runtime/server.log`, наличие Node и сообщение подготовки | В hidden-журнале есть ошибка порта, копии или хранения; BAT не ждёт результат серверного запуска |
| «Сервер работает со старым кодом…» | Закрыть вкладки старого планировщика, запустить вновь | Клиент требует storageVersion4; обновление страницы само не обновляет процесс сервера |
| Красный статус соединения после открытия | Сохранить экспорт правок, восстановить серверный запуск | При успешном ping обычная несохранённая запись повторяется; конфликт требует перечитать страницу |
| «Данные изменились в другой вкладке…» | Экспортировать нужную память перед обновлением | После обновления будет актуальная доска хранилища; экспорт можно анализировать/импортировать отдельно |
| «Хранилище занято…» либо оставшаяся instance.lock | Закрыть экземпляры и проверить указанный PID | Автоматического удаления lock или убийства процесса нет; ручное удаление допустимо лишь после проверки владельца |
| «Не удалось загрузить данные…» с ошибкой JSON/версии | Сохранить исходные файлы и прочитать ошибку/путь миграционной копии | Не заменять их пустым JSON; восстановление из UI доступно только после успешной загрузки приложения |
| Копии нет в открытом списке | Снова выбрать восстановление | Ротация могла удалить старую; UI обновляет список и предлагает другую |

`runtime/server.log` используется hidden-сервером: при размере более1МиБ
перед очередной записью журнал очищается. `data/server.log` старой установки
переносится только с проверкой байтов. PID и lock — служебное состояние,
не содержимое полного экспорта и не резервная копия доски.

Оставшиеся проверки: реальный Windows Shell/ярлык, фоновое ограничение таймеров,
сон/гибернация, потеря beacon и одновременное закрытие вкладок. Изолированный
серверный тест не доказывает эти сценарии в пользовательском браузере.

Основание: `start.bat`, `create-shortcut.vbs`, `start-hidden.vbs`,
`lib/launcher.cjs`, `lib/installation.cjs`, `server.js:findRunning/start/scheduleStop/shutdown`,
`app/js/core/keepalive.js`.
